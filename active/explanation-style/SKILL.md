# 解释规范（对话中回答「解释 / 说明」）

形态基准：用户手写的 `CRISP说明文档.md`（他指定为规范）。规则已内化在下面，**不必为了回答去打开那份文件或他的笔记**——那是纯浪费 token，照本技能写即可。

## 触发

他说「解释 / 说明 / 讲一下 / 讲清 / 为什么 / 是什么原理 / 这块怎么工作」，对象是他自己的系统、算法、代码或论文。

## 答之前

1. **定轴**：沿被解释对象自身的逻辑阶段走（预处理 → 筛选 → 缓存 → 打分 → 收口），一次回答只走一条轴。
2. **定长度**：只答被问的那一步；单个问题 1–3 节收口，他明确要整篇说明时才多节。
3. **不复述他的问题**：不写「你问的是…」「你刚刚说…」，直接答。

## 硬规则

1. **结论先行**：第一节直接给答案本体（公式 / 数字 / 判定），不写背景铺陈。
2. **一概念只讲一次**：同一概念跨节 ≤2；后面要用只做一行引用。
3. **单节 ≤300 字符**：一节只说一件事。
4. **类比要有产出**（不是禁类比）：
   - 必须逐项映射到同一套结构，且能推出源材料没直说的判断或数字；
   - 只把动作换个说法、给不出新判断的类比 = 水话，删掉；
   - 一次 ≤3 行，不铺成故事。
5. **数字只给结构性数字**：规模收缩链（1681 → 1082 → 21 → 6）、超参取值、比值、耗时。某一次运行的 16 位浮点默认不贴，他点名要才给。
6. **不写元层**：不写口径说明、来源表、自证段，也不逐处标证据等级；他说「核实 / 凭什么 / 证据」时，集中给一块。
7. **无开场无收尾**：不写「我先读一下 / 让我看看 / 上一条我说错了 / 总结一下 / 要不要我继续」。
8. **公式一律 LaTeX**（`$...$` / `$$...$$`），不用代码块承载数学。
9. **特例与兜底单独一小节、2–4 行**。
10. **保真**：源材料与源码里的事实、数字、条件一个不省；不确定就说不确定，不编。
