# 风险档 → 最小充分证据（verification strength by risk）

> 来源：ThreadGate 技能 `verification-before-completion` v0.1.0
> （`~/.codex/plugins/cache/threadgate-local/threadgate-workflow/0.1.0/skills/verification-before-completion/SKILL.md`，1186 B）
> 的档位口径与 `active/review-gate/SKILL.md` 的「## 路由」表对齐后合并。合并日期 2026-09-11。

## 核心判据

完成声明必须配**新鲜、可复现、与声明范围相称**的证据。**代理自述不是证据。**

| 风险档（与 review-gate 一致） | 变更类型 | 最小充分证据 |
|---|---|---|
| 免审 | 文档、格式、机械重命名 | `git diff --check` + 链接/渲染检查或目标字符串搜索 |
| 中风险默认 | 局部代码或脚本行为变更 | 目标测试、静态检查，或可复现的手工路径 |
| 中风险默认 | 配置变更 | 解析、启动/加载，或受影响路径的实际检查 |
| 高风险 | 共享契约、API/外部契约、持久化或迁移、权限、并发/幂等、缓存/队列、部署、跨 Agent 集成不变量 | 相关测试 + 静态检查 + 契约验证；行为变更按 `review-gate` 走 push 前独立 Review |

## 执行顺序

1. 明确**声明内容**与风险面（先写清要声明什么，再挑命令）。
2. 选择能证明它的**最小**命令。
3. 运行并读取真实输出。
4. 如实报告覆盖范围与盲区。

全量套件只在声明涉及全局回归、风险面需要它，或项目规则要求时才跑。

## 两条硬规则

- **「未检查」不得转为「通过」。** 没跑的东西只能报「未检查」，不能写成「通过」或「应该没问题」。
- **无法可靠判定风险档时，按高风险处理。**

## 子 Agent 回传后的核对

子 Agent 返回后，主 Agent 必须亲自检查实际 diff、产物或命令输出；验证不足时报告限制，**不得把局部检查说成全局通过**。
