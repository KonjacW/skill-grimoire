# 技能路由

先按任务风险选择最轻、仍能证明结果的路径。用户显式点名的技能、`AGENTS.md` 硬约束和平台上级指令始终优先。

## 三档入口

| 档位 | 可观察条件 | 动作 |
|---|---|---|
| 直通 | 单一范围、低上下文、无共享契约；包括只读问答、文档/格式和明确小改动 | 主 Agent 直接处理；不生成计划、不调用并行技能 |
| 轻量执行 | 普通多步任务，风险可定位且不需要跨会话 | 在内部维护轻量执行图：工作包、依赖、写入者、验证；不生成正式计划 |
| 正式计划 | 高风险、共享契约、迁移/权限/部署、跨会话，或需求缺口会改变方案 | 需要设计时先用 `plan` 收敛方案（未验证的假设先走 `spike`）；方案确认后把 `plan` 文档补齐「工作包 / 依赖 / 写入者 / 验收」四栏，补完即为正式计划，不再调用其他计划类技能 |

不要因为“可能有技能”而中断直通任务；也不要把直通误用于未确定接口或高风险行为。

## 一次并行判断

入口路由同时完成唯一一次并行判断。并行分两类，**任一类满足即可分片并行**；两类都不满足才串行（分级与任务卡规则见 `subagent-fanout-delivery/references/overlap-classification.md`）。

**A. 产出类 fan-out**（要写产物）：只有以下条件同时满足时，才使用 `subagent-fanout-delivery`：

- 至少两个可独立推进的工作包；
- 预计节省的时间或上下文明显大于派发、等待和集成成本；
- 文件、资源和契约边界可隔离。

**B. 只读勘察 / 取证类 fan-out**（搜索、清点、比对、审计、记录检索）：满足以下三条即**默认分片并行**，不必论证收益：

- 至少三个可独立推进的只读工作包；
- 各写不同产物文件；
- 写权互不相交。

这类任务零写冲突、集成成本仅为汇总，**不受 A 档「收益需明显大于派发与集成成本」的约束**。任务卡必写项、主 Agent 亲自复算关键数字、以及「先落盘报告骨架」的要求见 `subagent-fanout-delivery` 的《只读取证类 fan-out》节。

**C. 发散研究类（目标未定、要跑多轮）**：「多写几个产物」不是发散；**还没有答案、要靠多路探索把答案找出来**才是。**以下条件命中 ≥3 条即默认进入**（执行细则与《无人值守护栏》见 `subagent-fanout-delivery/references/iterative-research.md`）：

- 目标写成「提升 / 优化 / 改进 / 设计 / 找机制 / 找上限」这类，且**没有现成验收判据**；
- 已有至少一版基线或实测数字，且与目标差距可观（**有优化空间**，不是从零开始）；
- 至少 **3 个可独立推进**的方向（各自可量化、可各自落盘）；
- **一轮结不了题**（要用上一轮结论重定下一轮方向）；
- 允许跑多轮：时间与预算可承受，且**不在**「只评审 / 不要开始执行 / 只改这一处」这类约束下；
- **失败方向本身也算交付**（「此路不通 + 定量下界」可接受）。

进场后**先预注册这一波的判据（可算的量 + 阈值）再派发**——没有预注册的发散会退化成各写各的。用户不在场（长任务挂载、后台批次、离线）时，额外受《无人值守护栏》约束：波数与预算封顶、每波必配证伪、每波必须落盘收束、绝对禁止 push / 删除 / 越界改配置。

**第 7 条触发：闲时挂起**——主 Agent 正在等**自己控制不了的东西**（长批次 / 仿真结果未回、已派出的子代理未回、外部服务未响应），本轮没有别的可推进步骤，且手上信息已够（有基线 / 剖面 / 历史记录可用），同时命中上面 ≥3 条 ⇒ **把等待窗口用来发散**，而不是空转轮询或干等。闲时发散比无人值守更保守：默认**只派 1 波、只读 / 离线优先**（不许占用被等待工作所需的资源，重负载一律去服务器）、产物写独立位置、**等待对象一到就收束**，且**不许改动主交付物**（未验证结论只能进「待判清单」）。细则见 `subagent-fanout-delivery/references/iterative-research.md` 的《闲时发散》。

**不自动进场**（命中也要停）：用户明说只评审或不要执行；任务带硬性窄范围 / 只读约束；目标已明确且判据现成（走 A 档或 B 档）；推进必须做不可逆操作（先问）。

工作包数量本身不构成并行理由（A 档）；收益不足时主 Agent 串行处理。无法证明可隔离时串行。确定并行后才由 `subagent-fanout-delivery` 分级和生成任务卡（R1/R2/R3）；正式计划只记录该路由结果，不再次判断。最终计划、共享契约、最终写入、集成和验证仍由主 Agent 保留。

## 并行的成本门槛（实测刻度，用于 A 档的「收益明显大于成本」）

A 档那条判据曾经是纯定性的。以下刻度来自 2026-09-13 的一次本机审计（锚定窗口 2026-09-05 → 2026-09-13 UTC；口径 = 同父会话内 `started_at` 相差 ≤120 s 的子会话归一批，只统计宽度 ≥2 的批次，父侧按会话去重，未结束批次单列）：

| 事实 | 实测 | 用法 |
|---|---|---|
| 墙钟加速比（仅已结束批次 n=67） | 中位 **2.02×**，p10 1.40，p90 3.55 | 不按 n 倍预期 |
| 宽度 2 的批次（n=27） | 中位 **1.73×**，最低 **0.84×** | **n<3 不派** |
| 花费比：子 / 父 | 批次内 **0.82×**；窗口内全部子会话 **0.974×**；含缓存总 token **0.48×** | 「省不省 token」必须带口径 |
| 新鲜 token 比：子 / 父 | **1.20×**（批次内）/ **1.40×**（全部子会话） | 子代理重读上下文是真实开销 |
| 结果回灌主对话 | 338 条 / **457,533 字符 ≈ 18.3 万 token**；均值 1,354 字符/条 | 单条回报压到 ~1,200 字符：结论 + 数字 + 落盘路径 |
| 单位成本 | 见下方「计数口径」：**同一个量两种分母差 2 倍** | 引用时必须写明分母 |

**计数口径（最容易算错的一处）**：`单位成本 = 花费 / 工具调用数` 的分母有两种取法，结论完全不同——① 用会话表字段 `tool_call_count`：父 $2.84e-3 vs 子 $8.1e-4 = **2.8×**（8 天窗口下 3.5×）；② 按会话记录逐条解析出的真实调用数：父 $1.08e-3 vs 子 $0.82e-3 = **1.3×**。子代理两种分母**完全相等**（一次一轮、不批处理），父侧差 2.13×（父会在一轮里并发多次调用）——所以「子代理单位成本便宜 3.5×」**是分母口径的产物**，只能说「按同一字段比，子便宜 2.8×」。

**steer vs 重派（同日实测）**：向运行中的子代理发一条追加指令（steer）的**真实边际成本**中位 ≈ **$0.0010**（消息文本只占 5–7%，93% 是那一轮的缓存重发 + 输出）；重派要重付系统提示词与重建上下文：固定开销中位 **$0.0027**，真实子代理整单最低 **$0.0134** / 中位 **$0.064**。⇒ **重派 ≈ steer 的 2.7×（只算开机）/ 13×（比最便宜的整单）/ 64×（比中位整单）**。必须重派的反例：要改产物路径 / 返回 schema / 验收命令、原代理上下文已被污染、需要独立复核。

**宽度与止损（来自同日的第二份分析，口径不同源，只作量级参考）**：加速比中位 ≈ **0.75×n**（n=3 约 2.4×、5 约 3.1×、6+ 约 4.6×），**n ≤ 6 内效率基本不随 n 衰减**；**n≥7 掉到 0.58×n** ⇒ **单批 n ≤ 6**。子代理单路花费 $0.082–0.089 ⇒ **单路预算按 $0.09 封顶**。浪费面（异常/未结束/跨度>6h 的并集）= **11% 的路、10.8% 的钱**；但**僵尸会话占 89% 的墙钟却只花 6.9% 的钱** —— 时间与金钱脱钩，别用墙钟估预算。「其余路干等最后一路」的中位仅约 **1.7 min**，别把它与「末位派发后的批墙钟（中位约 11 min）」混为一谈。

两条口径纪律（不守会把结论算反）：**未结束 / `ended_at` 未回收的实例必须单列**（它会把批次跨度伪造成 36 小时、把加速比伪造成 0.5×）；**统计派发量按唯一键去重**（同一工具调用会被记成两行，实测 26 行 spawn 去重后是 21 个批次）。
