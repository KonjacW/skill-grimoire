# 计划执行回路（execution loop）

> 来源：ThreadGate 技能 `executing-plans` v0.1.0
> （`~/.codex/plugins/cache/threadgate-local/threadgate-workflow/0.1.0/skills/executing-plans/SKILL.md`，1880 B）。
> 合并日期 2026-09-11。**注意方向**：原文是独立技能；合并后它只是 `plan` 的执行侧回路——本技能已被吸收，不再作为独立技能名引用。

## 适用边界

用于执行**已批准**的书面计划（同会话或跨会话）。不用于普通轻量执行图，不重新设计方案，不重新判断是否并行。

## 开始前

1. 读计划，确认目标、验收、依赖、权限边界完整。
2. 核验工作区：基线、脏文件、目标路径、隔离条件是否与计划一致。
3. 只有计划明确要求隔离**且**用户允许时，才走 worktree（见 `finishing-a-development-branch` 的 `references/worktree-setup.md`）；非仓库或安全工作区不额外创建。
4. 发现会改变方案的缺口 → 停止并退回规划；局部执行细节可在不改变契约的前提下补齐。

## 回路（逐项任务）

**领任务 → 声明目标/边界/验证方式 → 执行 → 任务级验证 → 汇报 → 阻塞升级**

- 依赖满足后才标记「进行中」。
- 计划里已写明并行字段时，按 `subagent-fanout-delivery` 的 R1/R2/R3 执行，**不重新判断收益**。
- 每个任务跑它自己声明的验证命令并**记录证据**（实际输出，不是「应该通过了」）。
- 验证通过才标记完成，再释放后继任务。
- 等待远程作业或长进程时，可推进不争用资源且依赖已满足的任务；不得越过共享契约或写入所有权。

## 写入所有权

- **子 Agent 不得修改他人产物**（也不得写入共享最终工作区）。
- **每波结束，主 Agent 检查实际 diff**、验证结果、共享不变量和未决风险，再按顺序集成。
- 并行局部审查不替代最终集成 diff 的 Review。

## 停止条件

缺少依赖、权限不足、契约不清、验证重复失败、实际状态偏离计划 → 停受影响路径；其他独立路径可继续。只有缺口会改变**全局**方案时才请用户决策。

## 收尾

全部交付物完成后，按 `pre-commit-verification`（含其 `references/verification-strength-by-risk.md`）核验声明范围。
仅当用户选择分支集成或发布动作时才进入 `finishing-a-development-branch`。**本回路不授予 commit / push / 删除 / 发布权限。**
