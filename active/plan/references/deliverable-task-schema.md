# 交付物字段模板与计划自检

> 来源：ThreadGate 技能 `writing-plans` v0.1.0
> （`~/.codex/plugins/cache/threadgate-local/threadgate-workflow/0.1.0/skills/writing-plans/SKILL.md` 2531 B + 同目录 `plan-document-reviewer-prompt.md` 1947 B）。
> 合并日期 2026-09-11。本文件是**字段级的交付物模板**，不重新定义计划的保存位置与总体结构（那由宿主 `plan` 技能本体规定）。

## 交付物模板（8 字段，缺一不可）

```markdown
### 交付物 N：名称

- 文件路径：本交付物创建或修改的精确路径（可多个，逐个列出）
- 接口：对外暴露或被依赖的函数/命令/产物契约（含名称与签名）
- 依赖：前置交付物编号、数据或外部条件
- 验收命令：可直接复制粘贴执行的命令
- 预期输出：该命令应打印什么才算通过（不是「应该通过」）
- 边界：允许修改的文件、资源或逻辑区域；明确不许碰什么
- 回滚：失败时如何退回（备份路径、反向 patch、恢复命令）
- 完成判据：可观察的完成状态；未满足时不得标记完成
```

补充字段（仅在**已确定并行**时才写，否则整条写「串行」）：执行波次（Wave）、Depends on、R1/R2/R3 等级、最终写入者。

## 权限声明（必须写进计划正文，而不是靠默契）

**计划不自动授予提交权限，也不自动触发 Review。** 只有用户明确授权时，计划才加入 `commit` / `push` / 删除 / 迁移执行 / 外部发布步骤。
有仓库且产生行为变更时，push 前的独立 Review 由 `review-gate` 定义——计划只需引用它，不得代替它，也不得把「已计划 Review」当成「已通过 Review」。

TDD 判据（本文件自足说明，无需外部技能）：先写失败测试并确认它失败（RED），再写最小实现让它通过（GREEN），最后才重构。计划只标注该交付物需要 TDD 或针对性验证，**不**复制 RED/GREEN 步骤与完整代码。

## 保存前自检清单

- 每条验收都映射到某个交付物（没有孤儿验收）。
- 接口与名称前后一致（同一个东西不出现两个名字）。
- 没有 `TBD` / `TODO` / 占位符。
- 依赖无环；执行波次与入口路由的结果一致。
- 实施者**无需再次选择方案**即可开工。

## 计划文档审查（可选，派独立只读 reviewer）

计划写完、尚未开工时可派一次独立只读审查。审查项：

| 类别 | 查什么 |
|---|---|
| 完整性 | `TODO`、占位符、不完整任务、缺失步骤 |
| 与需求一致 | 覆盖 spec 要求，无重大范围蔓延 |
| 任务分解 | 边界清晰、步骤可执行 |
| 执行编排 | 并行波次理由充分、依赖闭合、重叠/写入权归属明确、集成门禁可验证 |
| 可构建性 | 一个工程师照此能否不卡住地做完 |

校准：**只报会导致实施出问题的缺陷**。措辞偏好与「锦上添花」不报。除重大缺口（缺需求、步骤自相矛盾、占位内容、任务模糊到无法执行）外一律给 Approve。
回传格式：`Status: Approved | Issues Found` + 逐条 `[Task X, Step Y]: 问题 — 为什么影响实施` + 建议（建议不阻塞通过）。
