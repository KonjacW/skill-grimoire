# 对话进展汇报（面向用户本人的成果汇报）

在**同一个对话内**持续维护一份**写给用户自己看**的中文进展汇报文件：用户随时（换会话、隔天、手机上看）只读这一份文件，就能知道这场对话聊到了哪、做成了什么、还差什么、卡在哪。

**不是交接文档**：交接给无记忆的下一执行者走 `agent-handover-prompts`；本技能是「同一对话内、面向用户本人」的实时档案，用词通俗、随对话滚动更新。

**也不是跨会话汇总**：本技能只管**当前这一场对话**。曾经有一条「每 30 分钟横切汇总多个会话」的定时链路（产出《长对话进展 · 最新成果》这类文件），已在 2026-09-15 按用户要求**删除**——现在 `report/` 下不该再出现那类文件。

## 验收线（先于一切内容）

用户**不看对话历史、不看聊天记录**，只打开这一份文件，就能回答三个问题：

1. 这场对话在做什么（一句话现状）；
2. 已经做到哪一步、最近发生了什么（按时间顺序）；
3. 还差什么、卡在哪、下一步是什么。

任何需要靠「对话上下文」才能看懂的地方（术语、缩写、背景、**推导出来的结论**、未在对话里明说的信息），都必须就地用大白话补一句说明——**读者假设零对话上下文**。术语首次出现时用通俗语言解释一遍。

## 触发（口令制：只有被启用的对话才写）

**默认状态是「不写」**。没有用户的明确启用，本技能不产生也不更新任何文件——哪怕对话里出现了天大的成果。「看到成果就自己开」的自动启动已于 2026-09-15 被用户明确取消。

- **启用（唯一入口）**：用户在本会话说「开汇报」，或给出等价指令（「这个对话写份 report」「开始维护进展汇报」）。
  - 启用动作 = **写启用标记** `<HERMES_HOME>/progress-report-on/<session_id>.flag`（内容写启用时间与主题，便于回溯）。
  - `<HERMES_HOME>` 本机 = `%LOCALAPPDATA%\hermes`（hook 的心跳就写在它的 `progress-report-state/` 下）。
  - `<session_id>` 怎么拿：在 `terminal` 里读**本会话的环境变量** `HERMES_SESSION_ID`（本机会直接给出形如 `20260915_142157_04a6aa` 的值，与 hook 写的心跳文件名 `<HERMES_HOME>/progress-report-state/<session_id>.json` 严格一致）。
    - ⚠ **不要**用「取 `progress-report-state/` 里 mtime 最新那个文件」来判定当前会话：本机常态是多会话并发（桌面端 / 网关 / TUI 并存），心跳由各会话**各自**写，「最新文件」属于最近发过调用的那个会话，不是**你所在的**会话。用错会把启用标记写到别的会话上 ⇒ 被启用的会话收不到提醒、没被启用的会话反而开始写。
    - 拿不到 `HERMES_SESSION_ID`（Codex 侧、外部脚本等）时**不要凭 mtime 猜着落笔**：把候选会话列表打给用户，让他确认是哪一个。
- **启用之后**：每次出现实质性进展（判据见下一节）就更新该对话的报告文件，并做对话播报。
- **停用**：用户说「关汇报」⇒ 删除该标记文件，立刻停止维护（已写的文件保留，不删）。
- **Hermes 侧维护提醒（不是触发器）**：`pre_llm_call` shell hook（`scripts/pre-llm-reminder.py`，宿主配置 `config.yaml` 的 `hooks.pre_llm_call`）**只在启用标记存在时**注入提醒，每新增 6 条消息提醒一次；没有标记时一律静默。它的作用只是「防漏更新」，开关始终在用户手里。
  - 复验：`hermes hooks doctor` 须有 `✓ allowlisted` + `✓ produced valid JSON`；`⚠ script modified since approval` **除外**（脚本改过就会有，属提示非故障，见下条）。
  - **行为复验要用 stdin 直喂真实载荷**——`hermes hooks test` 的合成载荷 conversation_history 为空（`is_first_turn: true`），永远不注入，测不出正例。复验时必须**显式给 `HERMES_HOME` 且写脚本绝对路径**（相对路径 + 未固定 HERMES_HOME 会落到 `~/.hermes`，得到假阴性）：

    ```bash
    HERMES_HOME="$LOCALAPPDATA/hermes" python "~/.codex/skills/active/conversation-progress-report/scripts/pre-llm-reminder.py" <<< '{"hook_event_name":"pre_llm_call","session_id":"__t__","extra":{"conversation_history":[1,2,3,4,5,6,7]}}'
    ```

    无标记应回 `{}`；建了 `<HERMES_HOME>/progress-report-on/__t__.flag` 之后再喂同样的载荷，应回 `{"context": …}`。
    复验收尾（别把测试残留留在真实 `HERMES_HOME` 里）：`rm -f "$HERMES_HOME/progress-report-on/__t__.flag" "$HERMES_HOME/progress-report-state/__t__.json"`。另需覆盖**历史变短**这一例（上下文压缩会整体替换 `conversation_history`）：先喂 300 条让它记账，再喂 40 条，**必须仍然注入**（脚本检测到历史回退会把计数归零）。
  - **脚本改动后 mtime 漂移只告警、不阻断执行**：注册只校验 `(event, command)` 对，脚本换了内容照常运行；`hermes hooks doctor` / `hooks list` 会一直报 `⚠ script modified since approval`，那是提示不是故障。
  - **重新放行必须走人工确认**：`hermes hooks revoke '<命令串>'` 之后，在**带 TTY 的终端**重启让确认提示出现，或显式 `HERMES_ACCEPT_HOOKS=1` 一次性放行。
    - ⚠ **不要**手工编辑 `shell-hooks-allowlist.json` 去刷 `script_mtime_at_approval`：那等于把「人在终端看过命令串再确认」降级成一个可被程序刷写的字段，且不留任何人工决策痕迹。
    - ⚠ 在**没有 TTY** 的进程里（桌面端 / 网关自动拉起）重新注册会**直接失败并静默跳过**，hook 整条链死掉。两种「没生效」别混：
      - **条目缺失**：`hermes hooks doctor` 会明确报 `✗ not allowlisted — hook will NOT fire at runtime`。
      - **条目在、但本进程启动时没注册**：`doctor` 查不出来（它只查 exec / allowlist / mtime / JSON 四项）——只能靠「新会话有没有产生心跳文件」判断；修法是重启到带 TTY 的环境重新注册。
  - **已在跑的进程**：注册条目常驻内存，但每次触发都是 spawn 新进程读磁盘脚本，所以脚本内容改动**下一轮即生效**；需要重启的是「revoke 之后重新注册」这类启动期动作。
- **Codex 侧**：没有 hook 机制，靠宿主 `AGENTS.md` 场景表的症状条目常驻生效（必须写症状，不能只写口令）。
- **口令总表（控制面）**：
  - 「开汇报」= 写启用标记并开始维护（没有成果的对话也能开）。
  - 「看汇报」= 把文件**全文**贴进对话（不是只给路径）；文件还不存在时如实说明「本对话还没开汇报」并给出默认落点，不要临时编一份。
  - 「关汇报」= 删启用标记，立刻停手。

## 更新节奏（纯事件驱动，不设兜底刷新）

**启用之后，更新用同一组判据**：只在有实质性突破时更新——不按轮数兜底、不按时间兜底。触发的事件：

- 完成一个阶段 / 里程碑；
- 做出关键决策，或用户定版；
- 踩到坑并记下教训；
- 口径、门禁、验收标准变更；
- 出现新的实质结果（实验出数、批次跑完、结论翻转）。

**「实质性」的判据**：这条信息会不会改变读者对「做到哪、还差什么」的判断？不会，就不更新——纯事件驱动不等于刷屏。反过来，真出现突破却忘了更新，是这份档案最大的失效方式。

## 汇报文件落点与命名

- 落点：`<OBSIDIAN_VAULT>/report/` —— 这是 Obsidian 库（vault）的**真身**（只有它带 `.obsidian`、`.git`）。
- `<OBSIDIAN_VAULT>/report/` 是坚果云同步出来的**副本**，由同步工具负责，**不要主动往那边写**（两边同时写会互相覆盖）。
- ⚠ 路径含特殊字符（单引号）⇒ 拼 shell 命令时用双引号把整条路径包住。
- 默认命名：`<对话主题>_进展汇报_<YYYYMMDD>.md`；**同一对话同一天反复编辑同一个文件**（覆盖式，文件顶部带「更新时间 HH:MM」）。
- **文件名范式以用户后续规范为准**——用户定稿前用上面的默认形式，不要自己另起一套。

## 通俗与写法

- **用最通俗的语言把进展说明清楚**：术语、缩写、内部代号首次出现时用大白话解释一句；写「改了哪一行、跑出什么数」而不是「进行了一系列优化」。
- 报告落在 Obsidian vault 里，写法**可以调用 `obsidian-notes` 技能**（中文笔记的措辞与标签规范）——它是本机已有的笔记技能，与本技能同源可用。

## 栏目骨架（沿用用户现有报告风格）

每份文件固定以下栏目，顺序不变：

1. **标题 + 更新时间**：`# <对话主题> · 最新成果`，下一行 `更新时间 HH:MM ｜ 本次更新：<一句话>`（同一对话里有并行的工作线时，每条工作线一个小节）。
2. **一句话现状**：这段对话 / 这场子任务现在处于什么状态（一个短句）。
3. **最近发生了什么**（按时间顺序，编号列表）：每一步做了什么、结果如何。数字、命令、输出一律照实写，不凭记忆。
4. **卡在哪 / 还差什么**：正在等的、没做完的、没验证的。
5. **下一步**：接下来要做的动作。
6. **诚实声明**：分三类标注——**实测**（有原始输出）、**推导**（有依据可复核）、**未核实**（明确没验证过）。禁止把推导 / 未核实写成实测。
7. **历史时间线**：按时间倒序追加一行「HH:MM 一句话」的流水，跨天不删、只增。

## 每次更新的对话播报

每次更新完文件，在对话里给 **3~5 行中文摘要**，必须含：改了什么 + 文件绝对路径。不要只写「已更新」。

## 收尾

任务做完（有结论、验收状态明确）时，写一份「终稿」：补结论与验收状态、把「还差什么」清成「无」，然后**删掉启用标记、停止维护**，直到用户再说「开汇报」。终稿不是交接文档；用户要交给下一个执行者时，另走 `agent-handover-prompts`。

## 陷阱

- **数字凭记忆 = 幻觉**：汇报里的数字 / 命令 / 文件路径只抄已核验来源（原始输出、已落盘文件），禁止改写或凭印象。
- **把「未核实」写成「通过」**：本机没跑过的编译、没出结果的批次，一律标「未核实 / 进行中」，不下提前判定。
- **文件名撞车**：同一对话只维护一个文件，跨天用新日期文件名，旧文件不删（保留历史）；同日多份同类报告会互相覆盖。
- **只维护不播报**：每次更新必须给摘要 + 路径，否则用户等不到任何信号。
- **纯事件驱动 ≠ 想不起来就不更新**：判据是「有没有改变读者判断的新信息」，不是「过了多久 / 过了几轮」。有突破必更新，无突破不刷屏。
- **和交接文档混用**：本技能写给用户自己看（通俗、实时）；`agent-handover-prompts` 写给下一执行者（交接、可复核）。用户说「交接 / 交给下一个 agent」时切到后者，别拿这份实时档案顶替。
- **越权的自动开**：没有启用标记就写文件 = 违反用户 2026-09-15 的定版规则。**默认必须不写**；「对话有成果」不是写文件的充分条件，「用户启用了这个对话」才是。
- **把 hook 当开关**：hook 只在**已启用**的会话里提醒「别忘了更新」，它既不负责开、也不判断有没有实质进展。没收到提醒 ≠ 可以漏更；收到提醒 ≠ 必须写。
