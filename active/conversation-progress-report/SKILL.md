# 对话进展汇报（面向用户本人的成果汇报）

在**同一个对话内**持续维护一份**写给用户自己看**的中文进展汇报文件：用户随时（换会话、隔天、手机上看）只读这一份文件，就能知道这场对话聊到了哪、做成了什么、还差什么、卡在哪。

**不是交接文档**：交接给无记忆的下一执行者走 `agent-handover-prompts`；本技能是「同一对话内、面向用户本人」的实时档案，用词通俗、随对话滚动更新。

**也不是跨会话汇总**：本技能只管**当前这一场对话**。`report/` 下已有的《长对话进展 · 最新成果》这类「多会话横切汇总」（按「场」分别叙述多个并行会话）由另一条链路产出，不归本技能维护——两者别写成同一份。

## 验收线（先于一切内容）

用户**不看对话历史、不看聊天记录**，只打开这一份文件，就能回答三个问题：

1. 这场对话在做什么（一句话现状）；
2. 已经做到哪一步、最近发生了什么（按时间顺序）；
3. 还差什么、卡在哪、下一步是什么。

任何需要靠「对话上下文」才能看懂的地方（术语、缩写、背景、**推导出来的结论**、未在对话里明说的信息），都必须就地用大白话补一句说明——**读者假设零对话上下文**。术语首次出现时用通俗语言解释一遍。

## 触发与口令（技能不会自动触发，必须靠路由条目）

- **启动**：用户说「开汇报」→ 开始维护。本技能**不主动问**，用户不说开就不动。
- **即时查看**：用户说「看汇报」→ 把文件**全文**贴进对话（不是只给路径）；文件还不存在（这场对话没开过汇报）时，如实说明「本对话还没开汇报」并给出默认落点，不要临时编一份。
- **停止**：用户说「关汇报」→ 停止维护，不再自动碰文件。
- 三个口令必须写进宿主的路由表（如 `AGENTS.md` 的场景表），否则技能索引里只有「名字 + 描述」，模型不会认得口令、技能形同虚设。

## 更新节奏（纯事件驱动，不设兜底刷新）

只在**有实质性突破**时更新——不按轮数兜底、不按时间兜底。触发更新的事件：

- 完成一个阶段 / 里程碑；
- 做出关键决策，或用户定版；
- 踩到坑并记下教训；
- 口径、门禁、验收标准变更；
- 出现新的实质结果（实验出数、批次跑完、结论翻转）。

**「实质性」的判据**：这条信息会不会改变读者对「做到哪、还差什么」的判断？不会，就不更新——纯事件驱动不等于刷屏。反过来，真出现突破却忘了更新，是这份档案最大的失效方式。

## 汇报文件落点与命名

- 落点：`<OBSIDIAN_VAULT>/report/`（Obsidian vault 根目录下的 report 文件夹，已存在）。
- 默认命名：`<对话主题>_进展汇报_<YYYYMMDD>.md`；**同一对话同一天反复编辑同一个文件**（覆盖式，文件顶部带「更新时间 HH:MM」）。
- **文件名范式以用户后续规范为准**——用户定稿前用上面的默认形式，不要自己另起一套。

## 通俗与写法

- **用最通俗的语言把进展说明清楚**：术语、缩写、内部代号首次出现时用大白话解释一句；写「改了哪一行、跑出什么数」而不是「进行了一系列优化」。
- 报告落在 Obsidian vault 里，写法**可以调用 `obsidian-notes` 技能**（中文笔记的措辞与标签规范）——它是本机已有的笔记技能，与本技能同源可用。

## 栏目骨架（沿用用户现有报告风格）

每份文件固定以下栏目，顺序不变：

1. **标题 + 更新时间**：`# <对话主题> · 最新成果`，下一行 `更新时间 HH:MM ｜ 本次更新：<一句话>`（同一对话里有并行的工作线时，每条工作线一个小节）。
2. **一句话现状**：这段对话 / 这场子任务现在处于什么状态（一个短句）。
3. **最近发生了什么**（按时间顺序，编号列表）：每一步做了什么、结果如何。数字、命令、输出一律照实写，不凭记忆。
4. **卡在哪 / 还差什么**：正在等的、没做完的、没验证的。
5. **下一步**：接下来要做的动作。
6. **诚实声明**：分三类标注——**实测**（有原始输出）、**推导**（有依据可复核）、**未核实**（明确没验证过）。禁止把推导 / 未核实写成实测。
7. **历史时间线**：按时间倒序追加一行「HH:MM 一句话」的流水，跨天不删、只增。

## 每次更新的对话播报

每次更新完文件，在对话里给 **3~5 行中文摘要**，必须含：改了什么 + 文件绝对路径。不要只写「已更新」。

## 收尾

任务做完（有结论、验收状态明确）时，写一份「终稿」：补结论与验收状态、把「还差什么」清成「无」，然后**自动停止维护**，直到用户再说「开汇报」。终稿不是交接文档；用户要交给下一个执行者时，另走 `agent-handover-prompts`。

## 陷阱

- **数字凭记忆 = 幻觉**：汇报里的数字 / 命令 / 文件路径只抄已核验来源（原始输出、已落盘文件），禁止改写或凭印象。
- **把「未核实」写成「通过」**：本机没跑过的编译、没出结果的批次，一律标「未核实 / 进行中」，不下提前判定。
- **文件名撞车**：同一对话只维护一个文件，跨天用新日期文件名，旧文件不删（保留历史）；同日多份同类报告会互相覆盖。
- **只维护不播报**：每次更新必须给摘要 + 路径，否则用户等不到任何信号。
- **纯事件驱动 ≠ 想不起来就不更新**：判据是「有没有改变读者判断的新信息」，不是「过了多久 / 过了几轮」。有突破必更新，无突破不刷屏。
- **和交接文档混用**：本技能写给用户自己看（通俗、实时）；`agent-handover-prompts` 写给下一执行者（交接、可复核）。用户说「交接 / 交给下一个 agent」时切到后者，别拿这份实时档案顶替。
