# Agent 交接文档（handover prompt）写作

把「成果证据 + 会话内知识 + 下一任务」压成**单文件、自包含、中文**的交接物，让没有任何记忆的执行者（Codex / 新会话 / Claude）能恢复状态、核对证据、直接继续——**用户不需要再说第二遍**。

## 验收线（先于一切内容）

交接后用户只发一条消息（贴文件 / 给路径 + 授权），全程不再补话。新执行者第一轮若开口问「密码怎么给 / 图什么口径 / 哪些禁碰 / 批次在哪个目录」，即为交接不合格。

同理，卡里**没有可判定的 Goal 段**、或启动语句**没让接手者进入 goal 模式**，接手者就判不了「做完没」——这条验收线同样不成立。两者已是机检项（见《生成流程》第 4 条）。

## 交接触发门禁（先判「该不该交接」，再谈「怎么写」）

核心判据一句话：**下一棒还能不能靠「同一执行者 + 上下文压缩」继续？能 → 继续，不能 → 交接。**

### 任务分级（先对号入座）
- **探索/科研类**（需长期连贯思维链，如算法探索）：默认**继续**，别主动交接。压缩是保连贯的必要损失，**不是交接信号**。只在「预注册门槛全部达成 + 无剩余待验证方向」或「用户显式下令」时交接。
- **机械执行/多产物类**：默认**拆分**，每个子 brief 自包含（子代理同样无记忆）。
- **长批次/无人值守类**：走 cron + 确定性指纹闸门，异常才唤醒。

### 反向判据（这些不是交接信号，别误触发）
- 上下文被压缩 → 是「继续」的信号，不是「交接」。
- 正处于密集交叉引用早期定版的收尾阶段 → 抑制交接，收尾完再说。
- 关键结论还没落盘 → 先落盘，交接 = 丢信息。
- **跨天 / 新线程不是自动的交接信号**：同一执行者仍能续（Codex 线程续接、Hermes 会话恢复、goal 未清）→ 继续；
  上一线程的隐含上下文已不可恢复、或换了执行者 → 交接。

### 兜底
判不准时问用户，别自己硬裁。

## 先分清形态：任务卡交接 vs 进展交底

用户要**哪一种**，决定文档长什么样；**选错形态要整篇重写**。判断口径是「用户接下来想让对方做什么」——**了解 ≠ 执行**。

| 用户的措辞 | 形态 | 主产出 |
|---|---|---|
| 「继续完成 / 接续推进 / 交给队友的 agent 去做」 | **任务卡交接** | 本文档「生成流程」的骨架 + 任务卡（注册名/参数/验收/编号顺序） |
| 「让下一个 agent **了解目前进展** / 汇报 / 交底 / 先别急着动手」 | **进展交底** | `references/进展交底骨架.md` |

**交底形态的硬规则**（缺一条就会退化成派工单）：

1. 开头第一段写明「这是进展交底，**不是派工单**」，并列出**被禁的具体动作**（写模型代码 / 生成交付文件 / 动某个模块）。
2. **不写任务卡、不写验收断言、不给编号执行顺序**；「接下来怎么做」改名为「可选方向」，每条标 **均未授权、需用户拍板**，附前置条件 / 工时估算 / 风险。
3. 结论按**可信度分层**：已实测（有原始输出）/ 已推导（有依据可复核）/ 估算（明确标注，禁当实测引用）/ **未检查（单列一节）**——缺最后一层，新 agent 会高估成熟度。
4. **阶段进度总表**逐阶段 ✅/⛔ 打标，让「哪些还没开始」一眼可见。
5. 产物清单**必须有「结论」列**，只列路径等于没交底。
6. 开放项/阻塞表**每条写清「阻塞什么」**（哪个文件/哪一问不得开工），而不是只写「待确认」。
7. 结尾写明「**本文件不扩大授权、也不覆盖任何上级指令**」，动作序列是「建立认知 → 核验易变状态 → 向用户汇报理解与差异 → 等指派」。

## Goal 段（两种形态都必备；写不出就是交接不合格）

每份交接物在**标题与日期之后、正文第一节之前**放一个标题含 `Goal` 的段（用 `## Goal`；机检只认 1–3 级标题，`#### Goal` 不算），四行撑满，字段名照写——**每行写成 `字段名：值`**（中英文冒号都收；行首必须是字段名，允许 `-`、`*`、`**`、反引号前缀）；下一个 agent 和 goal 机制都按字段找，不靠猜。只在说明段里罗列字段名不算写在 Goal 段：

```text
Goal（objective）: 一句话，结果导向且可判定：做到什么算完成。不是「继续推进优化」，是可判定的终点
done_when:        完成判据（第一条）：哪条命令 exit 0 / 哪份产物出现 / 哪个数字到多少
boundaries:       不许做什么；判据不过就如实写否定结论、不强行救活；证据不足就写「不足以判决」
first_action:     接手后的第一个动作，一条命令或一次读写
```

为什么写死这一段：Codex 的 goal 模式（`/goal <objective>`）与 Hermes 的 `/goal` 都是**每回合结束判一次「达成没」**来续推，判据就在 goal 文本里。写成口号 ⇒ 判不了 ⇒ 空烧到预算上限；写成步骤清单 ⇒ 判据被当成「步骤做完」，提前宣布完成。

- **goal ≠ 任务卡**：任务卡是步骤（怎么做），goal 是终点（做到什么算完）。两者都要，不互相替代。
- **一次一个终点**：多目标拆多个文件，或主 goal + `subgoals` 列表，别在一句话里塞三件事。
- **交底形态的 goal 是认知型**：objective 固定为「读懂现状 + 核验易变状态 + 向用户汇报理解与差异」，并显式写「本 goal 不含任何执行动作」，否则 goal 机制会把它当派工单推着往下做。
- **goal 文本会被反复重读**：写短、自包含；长参数表留在卡里，别塞进 objective。

## 生成流程（按序执行）

1. **盘点输入来源，按来源拉取，不手写**：
   - repo 定版 docs（证据、数字、口径）；AGENTS.md（环境、凭据机制、语言纪律）；
   - 本会话才有知识（红线/禁碰、踩过的坑、用户定版、in-flight 批次状态）；
   - 记忆常量（路径、凭据、项目惯例）。
   - 数字只抄已核验来源（JSON 汇总 / 已提交 docs），禁止凭记忆或改写。
   - **核验方式见《执行成本门槛》第 1 条：先列清单、再一次批量核，不要逐条现场查。**
2. **按骨架写**（可裁剪，但「Goal / 状态恢复 / 禁碰 / 口径 / 门禁 / 任务卡」六节必须有）：
   标题+日期 → 0 **Goal 段（四字段，见上一节）** → 1 目标与本轮结论一句话 → 2 状态恢复清单（必读来源 + 验证命令 + **预期输出**，不符即停不硬写）→ 3 已定版实现与提交（hash + 职责 + 语义）→ 4 本地测试与格式纪律 → 5 smoke/正式批次登记（目录名逐字符一致）与门禁字段 → 6 结果表（数字附录逐字抄）→ 7 用户定版规范 → 8 优化空间与推荐下一探针（规格/风险/验收/预估）→ 9 口径与硬门禁 → 10 服务器与同步（凭据机制引用、不写值）→ 11 dirty 清单 → 12 给下一 agent 的任务卡（两用：汇报层 + 执行层）。
3. **内嵌 vs 指针边界**：repo docs 已有的 → 给「指针 + 预期值」（该文件哪个节应有什么），不整段搬运；只内嵌会话内才有的知识（红线/口径/坑/定版/批次状态）。正文超 ~20KB 即警戒，先砍引用段。
4. **机检自检**（不是看手感）：CRLF=0（LF）、顶层节标题齐全、**Goal 段四字段齐全**、**启动语句含 goal 模式指令（`/goal`）**、关键数字 grep 命中、hash 语义正确、git 只新增目标 untracked 文件、**启动语句里的路径与磁盘文件名逐字一致**、**占位符/待填残量 = 0**（`<<…>>` 占位符与「待填」字样都算；「待拍板」这类正常内容不算）。
   **这九项已脚本化：`scripts/check_handover.py`，一次调用出全部结果 + 退出码，禁止逐项 terminal 手搓**（见《执行成本门槛》第 3 条）。
   行动型快照（要在同一个会话里记录尚未发生的动作，例如「先出交接再 push」、Review 三值、批次 wall-clock）**不要写两遍整份文件**：先照骨架写全，把未发生的那一段单列成一个 `### …回填（待…）` 小节，动作完成后**只重写该小节**（文件头与固定标题不动）再跑一次机检——既省一整轮墙钟，也不会出现「上半段已更新、下半段还是旧状态」的漂移（残留占位符会原样交给下一位）。
5. **快照时效**：文件名 `*_handover_YYYYMMDD.md`，默认不 commit；新证据（批次 complete / 新定版）出现即更新状态节；再喂前核对时效，过期就标 stale 或重写。
6. **目标工作区若有本地交接约定，整份服从它**：先读该工作区的交接目录 README + 索引，按它规定的**目录、文件名格式、正文前文件头字段、固定标题、索引登记、启动语句**写；本文档的骨架与默认保存路径只在该工作区没有约定时兜底。两个易错点：① **标题层级照现有快照定，不要照抄 README 代码块里的层级**（README 自身层级会把固定标题显示成低一级，照抄写出的是与全目录不一致的骨架）；② 索引里**只追加自己那一行**，不覆盖旧行、不刷新别人的快照。
7. **接继外部交接/审计摘要时先核验其引用的路径在本机是否存在**：路径可能来自别的机器/别的 agent 的工作区。整体不存在时穷举搜索（多盘根 × 目录名／文件名／提交哈希）并在产物里写明**搜索范围与零命中**，再退回「摘要条目 + 对本地代码与产物的逐条实测复核」；摘要里每条问题都要落到具体文件与行，落不到的另立「无法核实」条目，不把摘要当一手证据转述。

## 执行成本门槛（这条流程实测跑过 200+ 轮，必须先压）

实测（2026-09 三次真实交接会话）：交接文件本身只被写 **5 / 18 / 11 次**，但同期 API 轮数是 **235 / 218 / 162 轮**，每轮平均重发 **26~28 万 token** 的会话上下文。轮数不花在「写」上，花在**逐条现场取证 + 逐项机检**——一条命令查一个事实（`cd X && echo "=== A ===" && grep …`），而在长会话末尾每查一次就付一次全量重发。

三条硬约束：

1. **先列核验清单，再一次批量核**：动笔前把「要写进正文的数字」列成清单（哪个数字 / 从哪个源取），然后**用一个脚本一次全核**，产物落盘、正文直接引用脚本输出。禁止「一条命令查一个事实」的串行核验——那是把 1 轮能做完的事摊成 100 轮。
2. **只核验会写进正文的数字**：「新执行者可能问到、但文档里不写」的东西**不预先查**。验收线要求的是「不得缺席、不得自相矛盾」，不是「穷举预答」；真被问到再查，比现在便宜两个数量级。
3. **机检一次跑完**：用 `scripts/check_handover.py`——九项：行尾 / 占位符残留 / 节标题齐全 / **Goal 段四字段** / **启动语句含设置 goal 模式的指令** / 启动语句路径逐字一致 / hash 语义 / git dirty 白名单 / 关键数字命中（清单与《生成流程》第 4 条同一份），一次调用给出全部结果并带退出码。禁止逐项 terminal 手搓。

```
python scripts/check_handover.py <交接文档> --repo <仓库根> --allow-dirty <本文件相对路径> --must-contain <关键数字清单.txt> --expect-hash <commit>
# 退出码 0 = 无 FAIL；WARN 不阻断（未给 --repo / --must-contain 时各报一条 WARN）
# 关键数字清单 = 每行一个字面串（写进正文的数字逐行列出），全部命中才 PASS
```

**取证本身是只读 fan-out，默认分片并行**：核验清单覆盖 ≥3 个互不相干的来源（repo docs / 服务器状态 / 批次产物 / 本机历史）时，按 `subagent-fanout-delivery` 的《只读取证类 fan-out》派子代理。关键不在省墙钟，在**省上下文**：子代理从 ~16k 起步，而主对话是在 26 万 token 上每轮重发，同等工作量成本差一个数量级。主对话只保留「汇总 + 复算关键数字」。

## 内容必备（每类缺了都会逼用户开口）

1. **状态与环境快照**：HEAD + 验证命令 + 预期输出；dirty 纪律（能碰/不能碰、只 add 任务文件）；服务器只读 vs 可写目录；in-flight 批次与 manifest 查询方式；凭据有且只有一个注入点。
2. **负面知识（禁碰/已证伪）**：每条证伪路线带数字证据和证伪原因，区分「代码错误」与「数学上没有」；用户硬门禁独立成节（禁 test 集/ensemble/TTA/多 checkpoint/覆盖产物、禁依正式结果调阈值）；旧目录只读。
3. **口径与判定**：多口径（时间含/不含审计等）必须注明；跨家族比较只用真实同口径（构造产物如恒 0 字段禁用）；历史对照值标「历史 N 日、非本轮重测」；跨批次 wall-clock 注明并发/负载。
4. **验收门禁**：每 run JSON 门禁字段清单；smoke→正式顺序；**未出结果一律标「进行中」，禁止提前下判定、禁止写入定版节**；配对同口径与预注册容差。
5. **定版按交付物类型分别列**（图/UI/文档各自规范）；未指定的交付物类型默认「先问、不猜」，禁止拿另一类型的定版反向推断。
6. **任务卡与边界**：推荐下一步的注册名/参数/签名/状态行 + 风险 + 验收 + 编号执行顺序；中断规则分级（重试 N 次即停、门禁失败如实转备选方案不硬过、重大偏差停下问）；指令层级：交接物 > 旧计划，用户指示 > 一切。
7. **并行友好**：派生 N 个子 brief 时全部同规格源；每个子 brief 独立携带其任务所需完整上下文，不能要求子代理回头读主文档。
8. **启动语句（必写；任务卡交接六项全要，交底形态只留 ①②⑤⑥）**：文首给一段**可粘贴的单条消息**——用户的验收线是「只发一条消息（贴文件/给路径 + 授权）」，没有启动语句这条线不成立。必须含：① 交接文档与规格文件的**绝对路径**（与磁盘文件名逐字一致）；② 状态恢复第一步 + **预期数字**（不符即停、不要硬写）；③ **授权边界**（哪几波自主执行、哪些动作必须先问：`git push`/新建远端、任何删除）；④ **唯一门禁命令** + 「未过门禁不许报完成」；⑤ **打开 goal 模式、把《Goal 段》的 objective 原文设进去**（缺这条就不叫「持续推进」）：Codex 侧在新会话里发 `/goal <objective 原文>`（`/goal edit|pause|resume|clear` 可改；跑起来后状态显示 Pursuing goal / Goal achieved / Goal hit usage limits，预算用尽要 `/goal resume`，线程空闲时它自己接着干）；Hermes 侧用 `/goal` 或直接写 goal 状态（contract 五字段 outcome/verification/constraints/boundaries/stop_when，写法见技能 `hermes-session-operations` §6）——**Hermes 的 goal 只在每回合结束后判一次、没有新回合不会自跑**，所以启动语句要写清「启动后请发一条消息驱动」，或直接投给 Codex 会话；两边共同要求：做到 `done_when` 或触发中断规则前不要回来问方向，只在需要用户拍板时停；⑥ 语言与报告口径（中文、区分实测/估算）。**交底形态**删掉 ③④：那两项是执行授权与验收断言，交底明令不写任务卡与验收断言（见 `references/进展交底骨架.md` 硬规则 2）；⑤ 的 objective 写成认知型、`done_when` = 已核验的差异全部汇报完。Codex 侧没有 `hermes-session-operations` 这份技能时，按 contract 五字段 outcome / verification / constraints / boundaries / stop_when 直接写 goal 状态即可。禁止写「请阅读本文档」这类无路径的泛指。

## 陷阱

- **只投喂 plan 必缺上下文**：plan 只含任务规格，红线/口径/服务器运营/定版只在会话里 → 新执行者拿不全，用户被迫赘述。交接文档的职责就是把这些会话内知识结构化转储。
- **照抄规范样本会漏启动语句**：参照样本里若没有启动语句（常见形态是用「给下一个 agent 的下一步指令」一节代替），照抄骨架就会漏掉验收线的前置条件——启动语句必须自写，任务卡交接与进展交底两种形态都要。
- **同一批内容手抄到两份文档（execution prompt 与 handover 逐字重复）必然漂移**：单模板 + 按来源拉取，不复制粘贴旧段落。
- **数字无溯源 = 幻觉温床**：必须有「数字附录唯一规格源」+ 交付前 grep/校验命令。
- **凭据写进正文/明文**：只写机制引用（askpass/sshpass 名）与单一授权注入点。
- **新交付物类型没有定版就直接做**：agent 会拿旧定版猜（例：散点图定版被套到分布图上，产出被整体否决）——未指定的类型必须显式写「先问」。
- **喂过期快照**：批次从「进行中」变 complete 后旧交接物数字即失效，喂前先核对状态节。
- **形态选错**：用户说「让下一个 agent 了解进展」，却交出一份带任务卡与验收断言的派工单 → 整篇重写。同一次任务两份都要时（先交底、拍板后再派工）写成**两个文件**，并在交接索引里分别标注「进展交底（了解现状用，不指派）」与「任务卡版」，在交底里相互指路；**不要让一份文件兼任两用**——兼任必然写成派工单。
- **失效的止损线/关卡要点名作废**：交底里若保留了已被触发或已作废的时间线约束（探针提前通过、止损条件不成立），新执行者会把它当现行约束，做出多余动作。写清「该线已失效 + 依据」。
- **把交接做成「穷举核验」**：为了「数字可溯源」这一条，把每个数字都现场执行一遍验证命令 ⇒ 实测单次交接 162~235 轮，每轮都在 26 万 token 的上下文上重发，而交接文件总共只被写了不到 20 次。核验范围只限**将要写进正文的数字**，方式只限**一次批量脚本**（见《执行成本门槛》）。
- **多会话并发仓库里追 `--allow-dirty` 白名单是活靶子**（实测：连追 3 轮，每轮都冒出新的别人产生的 dirty 文件——`bench/**`、`work/<代号>-*/**`、`<临时上传目录>/**`、`docs/plans/**`，因为另外 4 个会话正在同时写）。正确做法：① 白名单**按仓库里已文档化的「写权范围」整目录列出**（一次列全，目录名覆盖其下级），而不是逐个文件追；② 用一条独立命令自证「我这次的改动全部落在自己的目录内」（`git status --porcelain | grep -E '<我的目录>|<我的记账文件>'`，输出应只有我自己的条目）——这条自证比白名单更稳、更有意义；③ 机检剩余的 WARN（远程路径 `~/xxx`、URL 被当成「本机路径不存在」）是误报，不要为它删改正文内容。
- **启动语句里的远程路径别写 `~/xxx`**：机检的「启动语句路径在磁盘上存在」会把 `~/<远程项目>` 当成本机路径判 FAIL ⇒ 远程家目录一律写成 `$HOME/<远程项目>`，远程路径一律带 `ssh <host> '...'` 前缀。同理，正文里成串出现的 `~/xxx` 会进 WARN 列表。
- **快照自身要 commit 时，别把「卡之前的 HEAD」写成预期值** ✗：卡片 commit 进仓库后 HEAD 就变成卡自己的 commit，接手者按字面核对必判「状态偏差」（实测遇到一次：卡声明 HEAD=3407f4b，实测 1003ea2 = 卡自身的 doc commit；同一坑在下一棒又差点重现）。固定写法：**写血缘不写死 hash** —— 「HEAD = 本卡 doc commit 或其后继（`git log --oneline -1 -- <卡路径>`）+ 核对 `git log --oneline -5` 里含指定几个 commit 且 `git merge-base --is-ancestor <卡之前的 HEAD> HEAD` 为真」，并保留回滚点。
- **Goal 段写成口号或步骤清单**：goal 模式每回合判「达成没」，口号判不了 ⇒ Codex 侧一路 `Pursuing goal` 烧到 token 预算上限（停在 `Goal hit usage limits` 等你 `/goal resume`），或反过来把「步骤做完」当达成、提前宣布完成。`done_when` 必须是可执行命令或可数产物。
- **只设 goal 不写 `boundaries`**：判据不过时 agent 会反复救活已判死的方向。把「判据不过就如实写否定结论、不强行救活；证据不足就写『不足以判决』」写进 boundaries——Codex 的 `blocked` 连续三次判定规则与 Hermes 的 judge 都吃这条。

## 参照样本

- 规范样本（12 节结构 + 数字附录 + 自检命令）：见你本地项目的 `docs/*/*_handover_YYYYMMDD.md`（数字附录唯一规格源的写法）。
- 前端/单机调试型交接变体（任务清单 A-F + 测试坑清单 + 不要做的事）：见你本地前端项目的 `docs/debug/*handoff*.md`。
- **两份参照样本都写于 Goal 段规则之前**：照抄它们的骨架会漏掉 `## Goal` 段与启动语句里的 goal 模式指令，机检这两项判 FAIL。
- **进展交底**（了解现状、不派工）的硬规则、三节骨架与形态判据机检命令：`references/进展交底骨架.md`。
